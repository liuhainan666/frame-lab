## 1. 完成定义（Definition of Done）

### 1.1 功能闭环

- [ ] 未登录可浏览模板与分类，可切换中文 / English，可进入登录页。
- [ ] 登录后可上传图片、看到预览与逐文件状态、提交任务；素材数量/类型/大小前后端双重校验。
- [ ] 任务提交后立即返回，后台顺序执行「素材检查 → 模拟生成 → 结果整理」，关闭页面不中断。
- [ ] 任务卡正确表达排队、恢复中、处理中、等待重试、成功、失败；查询异常不误判为任务失败。
- [ ] 多个任务各自更新、互不串扰；全部终态后停止轮询；刷新页面恢复登录态、历史与未完成任务。
- [ ] 成功后可在任务详情与结果预览中查看生成图；不提供下载、删除、重做。
- [ ] 账号切换后看不到上一账号的任务、素材或上传草稿。

### 1.2 可靠性扩展

- [ ] E-01：同一用户同一 `clientRequestId` 只创建一个任务；同键同载荷重放返回原任务；同键异载荷 409。
- [ ] E-02：可重试失败进入 `RETRYING`，按 2s/4s/8s 退避，最多 3 次尝试；尝试历史完整。
- [ ] E-03：服务重启后 `RUNNING` 任务恢复为 `QUEUED`，从中断步骤继续；已成功步骤不重跑。
- [ ] E-04：界面、模板文案、API 错误与任务消息支持 `zh-CN` / `en-US`；切换语言不跳路由、不丢登录态。

### 1.3 工程质量

- [ ] 后端 `./mvnw -B verify` 通过；前端 `pnpm lint && pnpm typecheck && pnpm test && pnpm build` 通过。
- [ ] `.github/workflows/ci.yml` 在 push / PR 执行同等检查。
- [ ] `docker compose up --build` 从空目录启动前端、后端、MySQL 与种子数据。
- [ ] README 覆盖版本、结构、启动、配置、接口、状态机、演示、已知限制、AI 使用说明。
- [ ] 仓库无真实密钥、`.env`、`storage/`、`target/`、`node_modules/`、`.next/`。

### 1.4 视觉与可用性

- [ ] UI-01 ～ UI-04 的主布局、信息层级、深色画廊气质与参考图一致；差异按第 5.8 节登记。
- [ ] 1440 / 1280 / 1024 / 768 / 360 无横向滚动；桌面双栏在 1024 以下正确堆叠。
- [ ] 英文界面无溢出、无关键信息截断；按钮与导航不因语言切换跳动。
- [ ] 键盘焦点可见；图标按钮有可读标签；弹层焦点陷阱与 Esc 关闭正确；状态不只靠颜色。

### 1.5 交付证据

- [ ] 08 的 P0 清单通过，阻断项为 0。
- [ ] 07 §8 的 8.1 ～ 8.11 与 08 §10 的 17 步演示可重复执行。
- [ ] 关键测试编号在 CI 或本地有运行记录；视觉对照截图归档。
- [ ] README 标注验收 commit；该 commit 在干净环境可启动。

### 2.2 明确不实现

- 真实 AI、支付、积分/会员、第三方账号、多区域部署。
- 模板管理后台、任务删除、重新制作、下载、视频处理。
- 消息队列、Redis、SSE、WebSocket、对象存储、病毒扫描。
- 多实例部署、步骤内部（渲染到一半）的精确续跑、无限重试。
- 参考图中的 credits、Premium、频道/工作流标签、账单、订阅、密码重置、服务条款、删除账号。
- Next.js Server Action / Route Handler 承载业务执行或任务持久化。

## 5. 页面实施与参考图对齐

### 5.1 对齐口径

需求 R-11 的原文要求是“参考对应页面的主要布局”“不要求还原品牌素材或逐像素一致”“截图中的题外功能不扩展正文要求”。据此分三层：

| 层级 | 内容 | 处理 |
|---|---|---|
| 硬约束 | 页面骨架与区块顺序、照片优先的深色画廊、顶栏层级、6 列竖版卡片、标题压底、制作台左右分栏、历史卡状态居中、账号分组卡片、状态语义与交互 | 必须与参考图一致；不一致即阻断 |
| 可调整 | 精确像素、圆角、边框、阴影、是否增加标题区、元信息密度、账号弹层宽度、动画 | 以 06 为准；差异登记，不擅自扩大 |
| 不实现 | credits、Premium、频道/工作流胶囊、账单、订阅、密码重置、服务条款、删除账号、删除/重做任务、下载、视频 | 与 01 的非目标一致；不得为了“像图”而加入 |

**优先级**：范围听 01，结构与层级听参考图，精确样式听 06，状态语义听 02/10。三者冲突时先改文档，再改代码。

### 5.2 UI-01 模板列表

**目标**：第一眼是“暗色墙面上的照片”，不是表单或仪表盘。

- 路由与数据：`/`；分类与模板均来自 Java API，不在前端写死数组。
- 首屏结构：顶栏（品牌、模板库/我的作品、语言切换、用户区）→ 紧凑标题区 → 横向分类栏 → 卡片网格。
- 网格：桌面 6 列（1440/1280），1024 约 4 列，768 约 3 列，480 约 2 列，360 无横向滚动；卡片 3:4、标题压底、封面优先。
- 必须对齐：深色背景、照片占主导、轻边框、克制强调色、分类横向可滚动、卡片标题在图片底部左侧、右上角用户区。
- 状态：加载骨架、空分类、请求失败与重试；筛选不整页刷新。
- 英文：标题最多两行；分类与顶栏不换行溢出。
- 验收：AC-R02-*、AC-R11-*、08 §6 UI-01、FE-U-01/02/28。
- 视觉证据：1280×800 默认、选中分类、英文、360px 四张截图。

### 5.3 UI-02 模板详情 / 制作台

**目标**：参考图的“左侧完成一次制作，右侧持续看结果”的分工不能变。

- 路由与数据：`/templates/[id]`；模板详情、上传、提交、当前模板任务列表。
- 布局：桌面双栏，左栏约 400px 且 sticky，右栏自适应；<1024 单列，上传在前、历史在后，CTA 在移动端可触达。
- 左栏顺序：返回 → 封面 → 分类/标题/描述 → 要求 → 上传位 → 通栏主 CTA；与 UI-02 的纵向节奏一致。
- 上传位：1 ～ 3 个，按模板要求渲染；空、选中、上传中、失败、完成五态；支持替换、移除、重试。
- CTA：未满足条件禁用并说明缺什么；提交中禁用；受理后恢复并清空草稿；同一次网络重试复用 `clientRequestId`。
- 右栏：`制作记录` + 刷新；当前模板最近 20 条；3 列任务卡；状态居中；不实现删除/重做。
- 状态：模板加载、模板不存在、历史空、历史请求失败、提交失败；不得把查询失败画成任务失败。
- 验收：AC-R03-* ～ AC-R08-*、08 §6 UI-02、FE-U-03 ～ 09。
- 视觉证据：1280×800 空上传、已上传、上传中、失败、任务处理中各一张。

### 5.4 UI-03 处理中、历史与结果

**目标**：用户不看文档也能分辨“排队、处理、等待重试、失败、成功、查询异常”。

- 任务卡状态：`QUEUED`、恢复中、`RUNNING`、`RETRYING`、`SUCCEEDED`、`FAILED`、查询异常七种展示；文案与视觉按 06 状态矩阵。
- 处理中：三步节点 + 当前阶段 + 第 N 次尝试 + 已用时；不使用假百分比。
- 等待重试：琥珀色而非失败珊瑚色；显示失败阶段、尝试次数、最近原因、约几秒后重试。
- 失败：显示阶段与可理解原因；可打开详情查看三步与尝试历史。
- 成功：结果图铺满卡片；打开结果预览；不提供下载。
- 查询异常：只显示提示条与恢复入口，保留最后已知状态。
- 历史页：全部/进行中/已完成/失败筛选；进行中包含 `RETRYING`；分页 20；活跃任务继续轮询，终态停止。
- 验收：AC-R05-* ～ AC-R09-*、08 §6 UI-03、FE-U-10 ～ 14/18/21 ～ 24。
- 视觉证据：处理中、等待重试、失败、成功、历史空态各一张。

### 5.5 UI-04 账号弹层与登录

**目标**：账号弹层保留参考图的分组卡片与信息层级，但只保留本题需要的身份与语言能力。

- 账号弹层：480px、圆角 24px；顶部头像 + 姓名 + 邮箱 + 角色；加入时间与数据范围；语言设置行；退出登录；关闭按钮 + Esc + 遮罩关闭。
- 不展示：账单、订阅、密码重置、服务条款、隐私政策、删除账号。
- 登录页：桌面左右分栏；登录卡 400px；演示账号可填入不自动提交；错误提示区分 401/429；`returnTo` 只允许站内路径；已登录访问 `/login` 直接返回。
- 语言：登录页与账号弹层均可切换；切换保留已输入邮箱与密码。
- 验收：AC-R10-*、08 §6 登录与账号、FE-U-16/19/20/25。
- 视觉证据：账号弹层、登录页错误态、登录页英文各一张。

### 5.7 视觉验收流程

| 重试预算错误 | 中断尝试消耗预算；耗尽后仍重试 | `INTERRUPTED` 不计数；恢复回退 `attempt_count`；BE-U-20/21 |
| 恢复重复执行 | 已成功步骤重跑；重复结果文件 | 从第一个非 SUCCEEDED 步骤开始；临时目录按任务隔离；BE-I-29/30 |
| i18n 漏翻 | 页面出现硬编码中文；英文溢出 | 词典集中管理；API 返回稳定码 + 消息；FE-U-25 ～ 30 |
| 容器/CI 拖到最后 | 本地能跑、Compose 失败 | M1 先起 MySQL；CI 骨架早建；M8 只做收口 |
| 范围蔓延 | 增加删除/重做/下载/积分等 | 以 01 非目标为准；新增必须走文档变更流程 |
| 安全回归 | 越权返回 403、静态目录可读素材、日志含令牌 | 归属查询带 `user_id`；私有目录；日志脱敏；08 §4.4 |
| 素材授权 | 封面来源不明 | 自制或免费可商用；README 记录来源；不依赖外部 CDN |
| 时间不足 | M6/M7 延期 | 只压缩 P1（URL 语言前缀、模拟页面、额外动效），不压缩 E-01 ～ E-04 与 P0 |

## 9. 交付与验收顺序

1. **静态审查**：01 ～ 11 与源码一致；无未实现却被文档声称完成的功能。
2. **构建**：后端 `verify`、前端四件套；CI 同等命令通过。
3. **自动化测试**：BE-U/BE-I/FE-U 关键编号通过；失败项有说明。
4. **容器**：删除数据卷后 `docker compose up --build`，确认迁移、种子、健康检查。
5. **功能演示**：按 08 §10 依次演示登录、列表、上传、成功、永久失败、可重试、重启续跑、幂等、语言切换。
6. **异常演示**：断网/500 不误判；多任务不串扰；切账号隔离；刷新恢复。
7. **视觉验收**：按 5.7 逐页对照；硬约束全通过；偏差记录完整。
8. **文档交付**：README 覆盖 08 §9；截图与测试证据可追溯；已知限制如实列出。
9. **验收 commit**：干净提交；README 记录哈希；该提交可在新环境一键启动。
