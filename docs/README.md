## 1. 目标

实现一个可独立运行的素材制作网站，形成完整业务闭环：

1. 访客浏览模板分类与模板卡片，查看模板详情和素材要求；界面支持中文 / English 切换。
2. 登录用户按模板要求上传图片，前端与服务端双重校验数量、类型、大小。
3. 提交后服务端立即返回任务 ID，由 Java 后台顺序执行「素材检查 → 模拟生成 → 结果整理」。
4. 用户在处理期间继续使用网站，可连续创建多个任务，并观察各自的状态与阶段。
5. 刷新页面或重新登录后，从服务端恢复个人历史任务、失败原因与可预览的结果图片。
6. 提供可重复触发的指定阶段失败、可调耗时、Docker Compose 一键启动和 CI 流水线。
7. **受理幂等**：同一用户同一 `clientRequestId` 只创建一个任务，重复请求返回原任务。
8. **自动重试**：可重试失败按次数与指数退避自动重试，界面展示等待重试、尝试次数与最终结果。
9. **断点续跑**：服务重启后从第一个未完成步骤继续，已成功步骤不重跑；中断步骤整步重试。
10. **国际化**：中文 / English 两套界面、模板文案与 API 消息；语言切换立即生效并持久化。

## 2. 非目标

- 不接入真实 AI、支付、积分/会员、第三方账号、多区域部署、第三方登录。
- 不实现模板管理后台、任务删除、重新制作、下载、视频处理。
- 不使用消息队列、Redis、SSE 或 WebSocket；异步用数据库任务表 + 后端工作线程 + 轮询完成。
- 不实现多实例部署、对象存储、病毒扫描。
- 不实现步骤内部（渲染到一半）的精确续跑；续跑粒度为步骤边界，中断步骤从头重跑。
- 不实现无限重试；重试只针对可重试失败，有次数上限与退避上限。
- 不把业务执行、任务状态或历史记录交给 Next.js 的 Server Action / Route Handler 完成。

## 3. 技术栈

| 层 | 选型 | 版本策略 | 说明 |
|---|---|---|---|
| 前端框架 | Next.js（App Router）+ React + TypeScript | Next 15.x / React 19.x / TS 5.x，锁定在 `pnpm-lock.yaml` | 业务页面为客户端组件，数据全部来自 Java API |
| 前端样式 | Tailwind CSS 4 + CSS Variables + Radix Primitives | 锁定在 lockfile | 自建设计系统，深色画廊风，不用重型组件库 |
| 前端状态 | TanStack Query 5 + Zustand 5 | 锁定在 lockfile | 服务端状态与登录会话分离；轮询按任务状态自适应 |
| 前端国际化 | 自建 TS 词典 + `NEXT_LOCALE` Cookie | 随前端源码 | `zh-CN` / `en-US`；语言切换清空并重取查询缓存 |
| 后端 | Java 21 + Spring Boot 3.4.x | `pom.xml` 锁定具体补丁版本 | 模块化单体，REST API |
| 安全 | Spring Security 6.4 + JWT（Nimbus JOSE） | 随 Spring Boot BOM | 无状态鉴权、BCrypt、刷新令牌、角色与资源归属校验 |
| 后端国际化 | Spring `MessageSource` + `Accept-Language` | 随 Spring Boot BOM | 错误、任务失败与步骤消息本地化；模板内容走翻译表 |
| 持久层 | MyBatis 3（`mybatis-spring-boot-starter` 3.0.x） | 锁定在 `pom.xml` | XML Mapper 写 SQL，不用 MyBatis-Plus |
| 数据库 | MySQL 8.4 LTS | Docker 镜像锁定 8.4.x | InnoDB、utf8mb4、UTC、Flyway 迁移；尝试记录 + 翻译表 |
| 迁移 | Flyway | 随 Spring Boot BOM | 启动时迁移；种子数据入库 |
| 文件存储 | 本地目录 + Docker Volume | 路径由环境变量配置 | 素材与结果均经鉴权接口读取 |
| 测试 | JUnit 5 + MockMvc + Testcontainers MySQL；Vitest + Testing Library + MSW | 锁定在 lockfile | 覆盖步骤顺序、失败中断、重试/续跑、幂等、多任务、i18n |
| 交付 | Docker Compose v2 + GitHub Actions | 见 [07](07-testing-ci-deploy.md) | 一条命令启动前端、后端、MySQL |

> 版本以锁文件为最终依据。根 README 必须列出实际使用的版本；本文档不把“最新版本”当作验收口径。

## 6. 六条硬规则

1. **服务端是唯一事实源。** 任务状态、阶段、失败原因、结果地址只认 MySQL 与 Java 返回值；前端定时器、按钮文案和本地缓存不得推导任务成功或失败。
2. **阶段边界必须可观察。** 三个步骤各自拥有独立的开始/结束持久化记录与事务边界；禁止用一个 `sleep` 包住全部流程，也禁止由前端定时切换阶段文案。
3. **用户数据严格归属。** 任务、素材、结果的每一次读写都带 `user_id` 条件；访问他人资源返回 404，不暴露资源是否存在。
4. **素材必须服务端可用。** 浏览器临时地址（`blob:`）只能用于预览；任务引用的素材必须是已落盘、已入库、可被 Java 校验的资产。
5. **查询失败 ≠ 任务失败。** 轮询接口超时、断网或 5xx 只改变“查询状态”，不得把任务标记为失败；必须保留最后一次已知任务信息并提供恢复路径。
6. **重试与续跑只从持久化边界继续。** 已完成步骤不重跑；中断或可重试的步骤整步重来；重试有次数与退避上限；每次尝试都留审计记录。

## 7. 关键术语

| 术语 | 英文 / 标识 | 含义 |
|---|---|---|
| 模板 | `template` | 一套素材要求与画布规则，如“旅行明信片” |
| 模板翻译 | `template_translation` | 按 `locale` 保存的标题与描述；缺翻译时回退基础中文 |
| 分类 | `template_category` | 模板筛选维度，如旅行风景、节日营销 |
| 素材 / 资产 | `asset` / `upload_asset` | 用户上传并已通过服务端校验的图片，属于某个用户 |
| 任务 | `task` | 一次制作请求，包含模板、素材、状态、阶段、结果或失败原因 |
| 步骤 | `task_step` | 任务的三个顺序阶段之一，拥有独立状态与时间戳 |
| 步骤尝试 | `task_step_attempt` | 某一步骤的一次执行记录：RUNNING / SUCCEEDED / FAILED / INTERRUPTED |
| 阶段 | `stage` | `MATERIAL_CHECK` → `GENERATE` → `FINALIZE` |
| 任务状态 | `status` | `QUEUED` / `RUNNING` / `RETRYING` / `SUCCEEDED` / `FAILED` |
| 等待重试 | `RETRYING` | 可重试失败后的退避等待；到期被 worker 重新认领 |
| 断点续跑 | resume | 服务重启后从第一个未成功步骤继续；中断步骤整步重跑 |
| 模拟控制 | `simulation` | 管理端可调的阶段耗时、指定阶段失败及是否可重试 |
| 工作线程 | worker | 从数据库认领 `QUEUED` 或到期 `RETRYING` 任务的后台线程 |
| 幂等提交 | `clientRequestId` | 前端为一次提交生成的 UUID，重复请求返回同一任务 |
| 国际化 | `locale` | `zh-CN` / `en-US`；错误码稳定，展示文案按请求语言本地化 |
| 归属 | ownership | 资源必须属于当前登录用户 |
