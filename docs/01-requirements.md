# 01 · 需求拆解、范围与验收映射

> 本文把 [需求.doc](需求.doc) 的 14 条需求翻译成可实现、可验收的设计决定。凡本文未列出的功能，默认不在 P0 范围。
> 需求原文的参考截图已固化到 [assets/reference](assets/reference)，分别对应 UI-01 ～ UI-04。

## 1. 题目性质与评分重点

- 这是全栈开发笔试题，总分 100，评价重点是：**后端多步骤异步处理、前端异步状态管理、页面与素材交互、用户身份与个人记录、工程交付及容器运行支持**。
- 实现复杂度不代表质量；“完整、可靠且能解释”优先于堆功能。
- 源码可证明的实现与实际运行效果分别记录；无法验证的部分如实写“未验证”，不隐藏问题。

设计对应策略：

| 评分关注点 | 本项目的主要证据 |
|---|---|
| 后端多步骤异步 | 数据库任务表 + 工作线程认领；三步独立事务、独立时间戳；失败即停，可重试则退避后重跑该步骤 |
| 可靠性扩展 | 受理幂等、可重试失败自动退避、服务重启按步骤续跑、每次尝试可审计 |
| 前端异步状态 | 上传中 / 提交中 / 排队 / 处理中 / 等待重试 / 成功 / 失败 / 查询异常八态分离；轮询按状态启停 |
| 页面与素材交互 | 模板筛选、上传位预览/替换/移除、逐文件进度、结果预览、失败原因、尝试历史 |
| 用户身份与记录 | Spring Security + JWT；个人任务按 `user_id` 隔离；刷新后恢复 |
| 国际化 | `zh-CN` / `en-US` 界面、模板文案、API 错误与任务消息；语言切换持久化 |
| 工程交付 | 测试矩阵、GitHub Actions、Docker Compose、README 清单 |
| 容器运行 | 前端、后端、MySQL、初始化数据一条命令启动 |

## 2. 产品定义

**FrameLab（素材工坊）**：一个深色画廊风格的素材制作网站。用户从模板库选择版式，上传符合要求的照片，服务端用可观察的三步流水线生成一张合成图片；作品与失败记录进入个人历史。

一句话验收：**未登录能逛模板；登录后能上传、提交、看到逐步进度；刷新后记录还在；指定阶段可以稳定失败；换账号看不到别人的作品。**

## 3. 角色

| 角色 | 能力 | 进入方式 |
|---|---|---|
| 访客 | 浏览模板列表、分类筛选、查看模板详情 | 无需登录 |
| 用户 `USER` | 上传素材、提交任务、查看与预览自己的任务、退出 | 种子账号登录 |
| 管理员 `ADMIN` | 用户全部能力 + 读取/修改模拟控制配置 | 种子管理员登录 |
| 后台工作线程 | 认领任务、执行三步、写状态与结果 | 服务进程内部，无 HTTP 身份 |

P0 不开放自助注册；两个普通种子账号用于演示“个人记录隔离”，一个管理员账号用于演示“失败注入”。

## 4. 范围

### 4.1 P0（必须完成，验收以此为准）

- 模板列表、分类筛选、模板详情，数据来自 Java API。
- 10 个模板、6 个分类（高于题目“至少 8 个模板、5 个分类”的底线），覆盖 1～3 张素材要求；封面为本地可访问文件。
- 登录、刷新会话、退出、当前用户；个人任务严格隔离。
- 上传图片：数量、MIME、大小前端即时校验；服务端重新校验并解码；预览、替换、移除；逐文件上传进度与失败重试。
- 提交任务：返回任务 ID；防重复点击；`clientRequestId` 服务端幂等。
- 三步异步：素材检查 → 模拟生成 → 结果整理；每步独立持久化、独立事务、可观察。
- 任务状态：`QUEUED` / `RUNNING` / `RETRYING` / `SUCCEEDED` / `FAILED`；当前阶段；失败阶段与原因；成功结果可预览。
- 多任务：可连续创建；两个工作线程；各自状态互不串扰；结束后停止跟踪。
- 历史记录：列表、时间、状态、失败原因、成功结果、尝试次数；刷新后恢复并继续跟踪未结束任务。
- 模拟控制：管理端 API 调整三步耗时；可重复指定阶段失败；可指定失败是否可重试；失败后停止后续步骤。
- 查询异常：保留最后一次任务快照，明确提示“暂时无法更新”，不得将任务改为失败；提供手动重试。
- 结果图：由服务端真实合成并落盘（Java2D），不是前端假图。
- **E-01 受理幂等**：`clientRequestId` + 数据库唯一键；重复/并发提交只产生一个任务，重放返回原任务。
- **E-02 自动重试**：可重试失败进入 `RETRYING`，按次数上限与指数退避自动重试；每次尝试独立记录。
- **E-03 断点续跑**：服务重启后 `RUNNING` 任务回到队列，从第一个未成功步骤继续；已成功步骤不重跑，中断步骤整步重跑。
- **E-04 国际化**：中文 / English 两套界面和模板文案；API 按 `Accept-Language` 返回本地化错误与任务消息；选择持久化。
- 工程：单元/集成/前端测试、CI、Docker Compose、README。

## 7. 核心流程

### 7.1 浏览 → 登录 → 制作

```
访客打开 /
  → 选择分类（Java: GET /api/templates?category=）
  → 点击卡片进入 /templates/{id}
  → 未登录：上传区显示锁定态，点击上传入口或 CTA → 登录并回到原模板
  → 登录后：选择图片并上传（POST /api/assets）
  → 全部就绪 → POST /api/tasks（202 + taskId）
  → 立即出现在右栏“制作记录”，按钮恢复可点击
  → 轮询 GET /api/tasks?templateId=...（仅活跃时）
  → 终态：成功显示结果图；失败显示阶段 + 原因
```

**设计决定**：未登录可以浏览模板与详情；上传位显示锁定层，点击触发登录并带 `returnTo`。登录后回到原模板并重新选择文件；不在前端暂存文件，也不允许匿名上传。这比为匿名用户暂存 `blob:` 草稿或提供匿名上传接口更安全、更可解释。

### 7.2 多任务

```
任务 A（素材检查）→ 任务 B（排队）→ 任务 C（排队）
worker-1 认领 A；worker-2 认领 B；C 等任一 worker 空闲
A 成功；B 在生成阶段失败且不可重试 → FAILED；C 继续执行
若 B 的失败可重试：B 进入 RETRYING，到点后重新排队
三张卡片各自更新；B 的失败不影响 C；C 结束后全部停止轮询
```

### 7.3 刷新恢复

```
刷新页面
  → AuthBootstrap 调用 POST /api/auth/refresh（HttpOnly Cookie）
  → 成功：内存保存 accessToken + user；失败：匿名态
  → 历史页 GET /api/tasks?page=1
  → 若存在 QUEUED/RUNNING/RETRYING：立即显示最新快照并开启轮询
  → 若全部终态：不轮询
```

浏览器刷新只影响前端；**服务端重启**由 E-03 处理：`RUNNING` 任务被回收为 `QUEUED`，前端看到的仍是“处理中”，任务自动从断点继续，无需用户操作。

### 7.4 失败演示

永久失败（默认）：

```
管理员 PUT /api/admin/simulation
  {delays:{materialCheckMs:800,generateMs:3000,finalizeMs:1200},
   failure:{stage:"GENERATE", remaining:1, retryable:false}}
  → 用户创建任务
  → 素材检查成功 → 生成阶段抛 StageFailureException
  → 该步骤 FAILED、后续 FINALIZE SKIPPED、任务 FAILED
  → task.failure_code=GENERATION_FAILED，failure_args 含 simulated=true
  → 再创建任务：remaining 已为 0，正常成功（可重复设置）
```

可重试失败：

```
管理员 PUT /api/admin/simulation
  {delays:{materialCheckMs:800,generateMs:3000,finalizeMs:1200},
   failure:{stage:"GENERATE", remaining:2, retryable:true}}
  → 任务第 1、2 次尝试均在生成阶段失败 → RETRYING（2s、4s 退避）
  → 第 3 次尝试成功 → 继续 FINALIZE → SUCCEEDED
  → GET /api/tasks/{id} 的 steps[1].attempts 有三条记录，前两条 FAILED
若 remaining 调到 3 或以上，第 3 次仍失败且达到默认上限 → FAILED，后续 SKIPPED
```

### 7.5 自动重试与断点续跑

```
自动重试（E-02）
  → 步骤抛可重试异常（RESULT_RENDER_FAILED / STORAGE_UNAVAILABLE / INTERNAL_ERROR）
  → 该次尝试 FAILED，task_step 回到 PENDING，任务 RETRYING，next_retry_at = now + backoff
  → 到点被 worker 认领 → RUNNING → 重跑该步骤（前序成功步骤不重跑）
  → 成功则继续后续步骤；最后一次仍失败 → FAILED + 后续 SKIPPED
  → 默认不可重试失败（MATERIAL_CHECK_FAILED / GENERATION_FAILED）直接 FAILED

断点续跑（E-03）
  → 服务在任务执行中重启
  → 启动恢复：RUNNING → attempt=INTERRUPTED、step=PENDING、task=QUEUED、resume_count+1
  → worker 认领后从第一个非 SUCCEEDED 步骤开始
  → 已完成步骤保留时间戳与消息，不重跑；中断步骤整步重跑
```

### 7.6 语言切换

```
访客/用户点击顶栏语言切换（中文 / English）
  → 前端写 NEXT_LOCALE Cookie（一年有效）并切换本地词典
  → 重新请求模板与任务（query key 含 locale），任务消息与错误随 Accept-Language 变化
  → 刷新后仍保持所选语言；未登录的模板浏览同样生效
  → 后端返回 Content-Language；不支持的 locale 归一化为 zh-CN
```

## 8. 关键设计决定

| ID | 决定 | 理由 | 代价 / 边界 |
|---|---|---|---|
| D-01 | Next.js 仅承担页面与客户端数据编排，Java 是唯一业务后端 | 满足 R-01 职责要求；避免业务逻辑双写 | 前后端需处理 CORS 与令牌刷新 |
| D-02 | 轮询更新任务，不用 SSE/WebSocket | 题目不强制；状态变化秒级足够；实现与验收更可控 | 存在最多约 1.5～2.5 秒延迟 |
| D-03 | 数据库任务表 + 工作线程认领（`FOR UPDATE SKIP LOCKED`），不用内存队列/MQ | 排队、重启后未开始任务可继续、状态天然持久化 | 单实例假设；启动恢复依赖单实例，多实例需改为心跳/租约 |
| D-04 | 素材与结果存本地目录，经鉴权接口读取 | 满足“服务端可用素材”，不引入对象存储 | 扩容需共享卷或迁移 S3 |
| D-05 | 访问 JWT 15 分钟放内存；刷新令牌 7 天放 HttpOnly Cookie | 避免 localStorage 泄露；刷新可恢复 | 跨端口开发需固定 `localhost`；多标签页共享刷新令牌 |
| D-06 | 结果由 Java2D 真实合成 JPEG | 结果可预览且不是假地址；失败注入 FINALIZE 有真实含义 | 仅模拟版式，不评价画面质量 |
| D-07 | 模板公开读取，任务与素材需登录 | 访客可逛；个人记录必须隔离 | 未登录上传不可用 |
| D-08 | 10 个模板 / 6 个业务分类，前端另加“全部”虚拟项 | 足够演示筛选与 1～3 张素材差异 | 非模板管理后台 |
| D-09 | 结果图只叠加英文品牌水印与序号 | 容器内不一定有中文字体，避免出现方块字 | 中文标题留在页面而非图片内 |
| D-10 | 不实现删除/重做任务、不实现下载 | 题目明确不要求；减少不可验收功能 | 界面不展示对应图标 |
| D-11 | 种子账号代替注册 | 身份策略自选；演示多用户隔离足够 | README 必须写明账号与限制 |
| D-12 | 提交带 `clientRequestId`，由数据库唯一键兜底幂等 | 防止双击/重试/并发产生重复任务 | 前端每次“提交意图”生成新 UUID；重放返回 200 + 原任务 |
| D-13 | 自动重试在**步骤**粒度，上限默认 3 次尝试（初始 + 2 次重试），指数退避 2s → 4s，封顶 30s | 无 MQ 也能验证退避与上限；步骤粒度保留已成功工作 | 需 `RETRYING` 状态与尝试表；等待期间占用一个状态值 |
| D-14 | 只有可重试失败才重试；业务性失败（素材不合格、模拟的生成失败默认）不重试 | 避免对确定性错误做无效重试；重试与否可解释 | 失败码需标注是否可重试；模拟控制提供 `retryable` 开关便于演示 |
| D-15 | 断点续跑在**步骤边界**：启动时回收 `RUNNING`，已成功步骤不重跑，中断步骤整步重跑 | 三步都是幂等的短任务，步骤级续跑即可验证；避免步骤内部状态机的复杂度 | 步骤内部不保留中间进度；续跑不消耗重试次数 |
| D-16 | 国际化用 `NEXT_LOCALE` Cookie + TS 词典；后端 `MessageSource` + `Accept-Language`；模板文案入库翻译表 | P0 不做 URL 语言前缀，避免路由与缓存复杂化；API 错误也能本地化 | 无独立语言 URL，不利于 SEO；翻译内容需与种子同批维护 |

## 9. 约束与假设

1. **单实例部署**：P0 只保证一个 Java 进程；多实例不在范围。启动恢复与任务认领都基于“进程唯一”这一前提；若未来扩容，需把启动恢复改为心跳/租约机制。
2. **时间**：数据库存 UTC（`DATETIME(3)`），API 返回 ISO-8601（`Z`），前端按浏览器本地时区展示；任务耗时以服务端时间戳为准。
3. **语言**：界面提供 `zh-CN`（默认）与 `en-US`；代码、枚举、日志键名、数据库字段用英文；后端错误码稳定，展示文案按请求语言本地化；模板与分类的展示文案存翻译表。不做第三种语言，不做按地区/时区自动切换，不做 URL 语言前缀。
4. **浏览器**：支持 Evergreen Chrome/Edge/Firefox/Safari 最近两个大版本；使用 `fetch`、`AbortController`、`URL.createObjectURL`、`<dialog>`/Radix Dialog。
5. **桌面优先**：1280px 为设计基准；360px 宽可完成浏览、上传、提交、查看结果，不追求独立移动端设计稿；两种语言均需在该宽度下可用。
6. **文件限制**：单文件默认 10 MB；模板可收紧到 5 MB；仅 JPEG/PNG；解码后像素上限 4000 万；超限拒绝。
7. **运行期离线**：除浏览器访问本站外，不依赖外部 CDN、图床或第三方 API；字体与词典在构建期打包。
8. **素材授权**：种子封面必须有可追溯授权（CC0/Unsplash/Pexels 或自制），来源写入 `CREDITS`；不使用公司内部或付费资源。
9. **数据规模**：演示数据 3 用户、10 模板、每用户几十个任务；任务列表分页默认 20，最大 50；模板列表一次返回全部 10 条。
10. **不做真实图片美化**：结果合成是确定性规则，不代表 AI 能力。
11. **可靠性边界**：重试仅限可重试失败码，最多 3 次尝试；续跑只在步骤边界；幂等窗口为同一用户 + 同一 `clientRequestId` 的终身去重；不做分布式锁、消息队列或跨实例调度。

## 10. 验收口径摘要

P0 必须同时满足：

- 全新环境按 README 一条命令启动，种子模板与账号可用。
- UI-01/02/03 的主要布局与信息层级匹配参考图，视觉按 06 的 Token 落地。
- 三个步骤顺序固定，任意阶段失败后无后续步骤执行；`task_step` 与 `task` 双处可读。
- 可重试失败进入 `RETRYING` 并按退避重试，尝试记录可查；达到上限后 `FAILED` 且后续步骤 `SKIPPED`。
- 服务重启后 `RUNNING` 任务自动回到队列并从第一个未成功步骤继续，已成功步骤不重跑。
- 同一 `clientRequestId` 重复或并发提交只产生一个任务，重放返回原任务。
- 中文与英文界面均可完成完整流程；API 错误与任务消息随 `Accept-Language` 变化；刷新后语言保持。
- 刷新页面后历史与进行中任务恢复；换账号看不到他人数据。
- 停掉后端再恢复，前端显示“查询异常”而非“任务失败”，任务恢复后继续更新。
- CI 在 push/PR 上执行并通过；测试能证明步骤中断、重试上限、续跑、幂等、多任务隔离与语言回退。

完整逐项清单见 [08-acceptance.md](08-acceptance.md)。
