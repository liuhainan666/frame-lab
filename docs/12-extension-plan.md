### 1.3 判定规则

1. **P1 不改变 P0 验收。** 08 的签署结论继续有效；扩展验收单独留证。
2. **每项必须有可观察验收。** 不接受“加了代码但没有可复现证据”。
3. **跨越非目标先改文档。** 多实例、Redis、对象存储、SSE、任务重试等条目，先修订 01/05/10，再排期。
4. **安全与数据正确性优先于可见功能。** 同一时间段内，先做会话安全与数据卫生，再做注册、SEO 等产品面扩展。

## 5. 明确不做

以下条目保持 [01 §4.3](01-requirements.md) 的边界；本文不把它们包装成“扩展”重新引入：

| 类别 | 条目 |
|---|---|
| 业务 | 真实 AI、支付、积分/会员、订阅账单、第三方账号、第三方登录 |
| 模板 | 模板管理后台、模板 CRUD、模板审核流 |
| 任务 | 任务删除、重新制作、结果下载、视频处理、无限重试 |
| 架构 | 多区域部署、集群、消息队列、Redis、对象存储、病毒扫描、步骤内部精确续跑 |
| 前端 | Next.js Server Action / Route Handler 承载业务执行或任务持久化 |
| 参考图 | credits、Premium、频道/工作流标签、账单、密码重置入口、服务条款、删除账号 |

**条件性例外**：X4 的多实例、共享存储、Redis、可观测性，以及 P1-07 的 SSE，均与 01 的“明确不做”冲突。只有在部署要求变化、且 01 完成修订评审后，才允许启动 X4；否则 X4 只是备选路线，不进入排期。

**“人工重试”与“重新制作”的边界**：01 明确不做“重新制作”；A-09 的人工重试如果实现，必须定义为“对失败任务创建新任务并记录 `retry_of_task_id` 与审计”，而不是原地重置任务。该定义仍需产品确认，默认不做。

### 6.3 X1 · 安全与会话（3 ～ 4 人日）

**目标**：刷新令牌真正轮换、重用可检测；禁用/改密/全部退出后访问令牌立即失效；前端刷新逻辑不进入死循环。

**数据库（V3，禁止修改 V1/V2）**

| 变更 | 说明 |
|---|---|
| `app_user.token_version INT UNSIGNED NOT NULL DEFAULT 0` | 访问令牌携带 `ver`；递增即让旧令牌失效 |
| `refresh_token.family_id CHAR(36) NOT NULL` | 同一次登录派生的令牌家族；旧数据用 UUID 回填 |
| `refresh_token.family_expires_at DATETIME(3) NOT NULL` | 家族绝对过期；轮换不延长 |
| `refresh_token.replaced_by_id BIGINT UNSIGNED NULL` | 轮换链，便于审计与重用判断 |
| `refresh_token.revoked_reason VARCHAR(24) NULL` | `LOGOUT` / `ROTATED` / `REUSE` / `DISABLED` / `EXPIRED` |
| 索引 | `(family_id)`、`(user_id, revoked_at)`、`(expires_at)` 已有则复用 |

**后端任务**

| 编号 | 任务 | 关键点 | 验收 |
|---|---|---|---|
| X1-01 | V3 迁移与回填 | 只新增列/索引；旧行 family 回填；不破坏 V1 约束 | 空库与已有库都能迁移；Flyway 校验通过 |
| X1-02 | 刷新轮换 | 事务内锁定旧令牌；旧令牌标记 `ROTATED` 并写 `replaced_by`；签发同 family 新令牌；旧令牌重用 → 撤销整个 family | 轮换后旧令牌 401；重用触发家族撤销；日志有 `auth.refresh_reuse_detected` |
| X1-03 | 并发刷新策略 | 合法多标签并发不得误登出；采用后端 30s 宽限兜住并发，前端保留单标签单飞；确认的重放必须撤销家族 | 宽限内重复刷新不撤销家族；超宽限重放撤销家族 |
| X1-04 | 访问令牌即时失效 | JWT 增加 `ver`；过滤器校验 `status=ACTIVE` 且 `token_version=ver`；禁用/改密/全部退出递增版本 | 禁用用户持旧 access token 下一次请求即 401；无每请求 N+1 |
| X1-05 | 全部退出 | `POST /api/auth/logout-all`：撤销全部 refresh 家族 + 递增 `token_version`；可选 `GET/DELETE /api/auth/sessions` | 退出全部后所有旧令牌失效；当前会话也失效 |
| X1-06 | 前端适配 | 单飞刷新保留；轮换失败清理会话并回登录；不引入 localStorage token；错误不重试风暴 | 刷新成功后继续原请求；失败只跳转一次 |
| X1-07 | 测试与文档 | 后端轮换/重用/禁用/登出全部；前端刷新失败；更新 02/04/05/07/10 | 新用例全绿；P0 用例无回归，当前 102 项通过 |

**设计约束**

- 每请求一次 `app_user` 主键查询换取即时失效；若压测显示瓶颈，才加 ≤30s 短缓存，并在 05 记录窗口。
- 刷新 Cookie 保持 `HttpOnly`、`SameSite=Lax`、生产 `Secure`、`Path=/api/auth`；轮换时重设 Cookie。
- 不记录原始刷新令牌、JWT、密码；只记录哈希、family、用户与结果。
- 轮换提供配置开关 `FRAMELAB_REFRESH_ROTATION_ENABLED=true`；异常时可关闭并保留旧令牌至过期，作为回滚手段。

**退出条件**：轮换、重用检测、禁用即时失效、全部退出四类用例通过；既有 P0 登录/刷新/退出/账号隔离全部回归；`./mvnw -B verify` 与前端四件套绿。

## 9. 工程规则、回滚与证据

### 9.1 变更规则

1. **迁移只向前**：新增 `V3__...` 起；V1/V2 永不修改；破坏性清理先 dry-run。
2. **API 向后兼容**：新增字段/端点优先；破坏性变更必须升文档版本，并在同一批改前端类型、MSW、测试。
3. **契约同批**：DDL、DTO、错误码、前端类型、夹具、测试、02/04/07/10 一起改；不允许只改一边。
4. **功能开关**：注册、SSE、素材清理、刷新轮换、模拟页均有开关或权限边界；默认值安全。
5. **安全不变量**：access token 不落 localStorage；日志不含令牌/密码；Cookie `HttpOnly`/`SameSite=Lax`/生产 `Secure`；越权 404；管理端 403。
6. **性能**：清理任务批处理并走索引；token 版本校验若每请求查询，需在 05 记录成本与压测结果；避免 N+1。
7. **提交**：按 [09](09-git-commit.md) 分层提交；一个提交一个模块/层次；不 push；不提交秘密与运行数据。

### 9.2 回滚

| 场景 | 回滚方式 |
|---|---|
| 轮换导致登录循环 | 关闭 `FRAMELAB_REFRESH_ROTATION_ENABLED`，恢复旧令牌至过期；前端回退刷新逻辑 |
| 清理误删风险 | 先 dry-run；真实运行前备份 DB + 存储；关闭调度开关；不删除未知文件 |
| 注册被滥用 | 关闭注册开关；保留已注册账号；必要时禁用账号 |
| E2E/契约检查拖慢 CI | 先设非阻断并留报告，稳定后再阻断；不回退已有单测 |
| 迁移需撤销 | 不写 down 迁移；部署上一版应用（新列可空/有默认值），确认兼容后再清理 |

### 9.3 证据

- 每阶段一个 `docs/evidence/extensions/x*-acceptance.md`：范围、命令、结果、截图/日志、未决项。
- 视觉类证据（模拟页、URL 语言、账号安全）附 1280/768/360 截图与中英对照。
- CI 证据记录工作流名称、运行链接或本地等价命令输出；远程 Actions 未 push 时标注“本地等价验证”。
- README 增加“可选扩展”一节，只列已实现项；未实现项留在本文，不写成已完成。
